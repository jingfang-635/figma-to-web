# cells[] 契约（强制，画出来的矩形）

有些设计事实是**画出来的矩形**：它既不是控件（`controls[]` 的 geom 角色会去和表单控件配对），也不是图标（没有符号身份），也没有文案。日历/网格的 chrome 就是典型。这类矩形必须进 `cells[]`，否则它没有任何一个腿能看见——像素腿被活数据遮罩挡掉、geom 腿找不到可配对的控件、text 腿没有字符串、icon 腿没有字形，页面把整片网格刷成纯白也能全绿。

`cells[]` 逐槽列出该屏每一个**非数据类型**的可见矩形（`schemas/layout-ir.schema.json`）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `nodeId` | 是 | 该槽在 `tree` 中的节点 id |
| `role` | 是 | 见下角色表；与 `controls[]` 的 geom 角色、`icons[]` 的 role 互斥 |
| `bounds` | 是 | 槽的绝对框，用于盒配对 |
| `fill` | 否 | 该矩形实际画出的底色（`$defs.paint`）；写屏据此取色 |
| `sample` | 否 | `true` = 活数据样本，**不参与盒配对**，只提供 paint/尺寸给消费端 |

| role | 用于 | 配对方式 |
| --- | --- | --- |
| `frame` | 网格/日历的外框 | 盒精确 |
| `grid-head` | 网格表头行/表头格 | 盒精确 |
| `grid-cell` | 网格数据格 | 盒精确；`fill` 按**整列**校验（见下） |
| `legend-swatch` | 图例色块 | 盒精确 |
| `badge` | 跟随游标的徽标（今日圆标） | **只比尺寸与底色**，位置自由 |
| `toggle-track` | 分段开关的外轨 | 盒精确 |
| `toggle-pill` | 分段开关的滑块 | 用 `sample: true` 出槽（位置随选中项移动） |

规则：

- **活数据样本用 `sample: true`**：格内 chip、滑块这类「一个数据一条」的矩形，其**条数**由数据决定，不能当成布局事实断言；但它们的尺寸与底色是设计事实，要留下来给写屏用。
- **整列一致性是强断言**：IR 对某一列的所有 `grid-cell` 一致着色时，闸门要求运行时该列保持该底色（用来抓「整片网格刷白」）。因此「某列是同一个底色」这一事实必须靠**把该列每个格都列出来并带同一个 `fill`** 表达，不能只列一个代表格。
- **位置自由的槽也要出槽**：`badge` 每月的 y 都会变，`bounds` 只是模板；仍必须出槽，否则尺寸与底色无处可校验。
- 底色一律写进 `fill`，写屏从 IR 读色。把 IR 里的颜色抄成 CSS 字面量会被 impl 腿抓（`GATE_IMPL_HARDCODED`）。
- 枚举/回填/自检用 `node scripts/ir-cells.mjs`（`--list` 看槽，`--write` 回填并同步 webDir 生成镜像，无参即自检）。

自检与完成判据见 `SKILL.md`；测量侧判据见 `gate-cells`。
